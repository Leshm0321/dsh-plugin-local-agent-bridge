# 功能

面板能做的全部事情，大致按你遇到它们的顺序排列。[README](../../README.zh-CN.md) 讲怎么把它跑起来，这里讲跑起来之后有什么。

下面大部分内容由一条规则塑造：每个产品都被问过它实际能做什么，也只提供这些。两者不一致的地方——Codex 报告三种权限模式而 Claude Code 有五种、Claude Code 在跑过一轮之前列不出自己的模型——如实呈现差异，而不是抹平。一个悄悄做了别的事的控件，比一个干脆不存在的控件更糟。

## 输入框


| 按键 | 作用 |
| --- | --- |
| Enter | 发送 |
| Shift+Enter | 换行 |
| `↑` / `↓` | 翻已发送过的消息（输入框为空时） |
| Esc | 打断进行中的一轮，否则清空草稿 |
| `/` | 产品报告的命令与技能 |
| `@` | 工作目录下的文件 |

输入法组词过程中的 Enter 会被忽略，所以选中候选词不会把一句半成品发出去。

`@` 在任何一个词可以开始的位置都生效，因为引用文件是发生在句子中间的；选中之后只替换那一个 token。搜索跑在主机上，在符号链接解析之后限定在工作目录内，受访问预算约束，并跳过 `.git` 和依赖目录树。提前停止时它会直说，而不是把一份不完整的列表当成完整的呈现出来。

输入框周围的控件跟随各产品自己的输入框布局：

| 位置 | 显示 |
| --- | --- |
| 上方左侧 | 工作目录、分支、改动行数 |
| 上方右侧 | 已花的 token，以及上下文占用 |
| 下方左侧 | 权限模式、文件按钮、语音输入 |
| 下方右侧 | 用量额度、模型、发送 |

**输入框上方的状态行**回答终端一眼能回答的那些问题。分支和改动规模来自 `git status --porcelain=v2` 与 `git diff --numstat HEAD`，在主机上执行、不继承环境变量、并关掉了终端提示与索引锁，所以一次状态读取既不会卡在等凭据上，也不会和你自己的终端抢锁。不是仓库的目录、或者没装 git 的主机，就干脆什么都不显示。detached HEAD 会给出它的提交并说明这一点；没有跟踪上游的分支也会说出来——因为等到 push 之后才发现就太晚了。

已花的 token 是这个会话的累计值，悬停时显示输入、输出、缓存读取和缓存写入。它和旁边的上下文用量条回答的是两个不同的问题——一个只会增长，另一个随会话压缩而双向变动——所以两个都在。

**文件按钮**提供三条路径，因为文件可能在三个地方：

- **工作目录**就是不用敲语法的 `@`——同一套主机搜索，列出文件和文件夹，把引用追加到草稿里。不复制任何东西。文件夹保留尾部斜杠，两个产品都是靠这个把它和文件区分开的。
- **这台电脑**从运行浏览器的那台机器发送文件。当 Harness 在别处时，这是那些字节唯一的到达方式。它们落在工作目录内的 `.dsh-bridge-uploads/` 里——记得把它加进 `.gitignore`——引用方式完全相同，所以两种来源在产品看来是一种形状。
- **主机文件系统**浏览运行 Harness 那台机器，可以越出工作目录，并按绝对路径引用你选中的东西。点击目录即打开；引用一个目录要通过它自己的按钮，所以一次点击永远不会有两种含义。以点开头的条目在你要求之前保持隐藏。

浏览主机是面板范围最宽的一次读取，而且可以关掉——它授予了什么、没授予什么，见[浏览主机文件系统](security.md#浏览主机文件系统)。

上传是这个桥接里唯一会写主机文件的路径，所以刻意收得很紧：目的地唯一且浏览器无法指定、文件名按白名单重建而不是照信、符号链接解析之后重新校验包含关系、任何东西都不覆盖，上限为单文件 8 MB、单请求 32 MB、50 个文件。无法弄安全的名字、或者超限的文件，会被拒绝并计数，而不是默默丢掉。

**语音输入**只在浏览器有 Web Speech API 的地方出现，实际上就是 Chromium 系。转写结果是追加的，所以说话是延长一个打出来的句子、而不是替换它。注意浏览器的识别未必是本地完成的——见[安全边界](../../README.zh-CN.md#安全边界)。

## 侧边栏


折叠按钮在标题栏左侧，和它控制的那个侧边栏同一侧。折叠后，侧边栏变成 52px 的图标窄栏，仍然可以切换会话——进行中的一轮显示为一个点——内容区把宽度收回去。

## 权限模式


这些模式沿用 Claude 桌面应用的叫法，因为操作者已经熟悉那套词汇：

| 模式 | 含义 |
| --- | --- |
| 自动 | 由 Agent 自行处理权限决定 |
| 手动 | 做任何改动之前都先问 |
| 接受编辑 | 自动接受所有文件编辑 |
| 计划 | 改动之前先出计划 |
| 绕过权限 | 接受所有权限 |

每个产品只报告它真能遵守的模式，所以屏幕上的模式永远就是 Agent 遵守的模式。Claude Code 五种都有原生对应。Codex 报告三种：它没有「接受编辑」这种策略，而它的计划模式只能通过一个会覆盖你在主机上配好的模型和推理强度的载荷才能进入。

**「接受编辑」和「绕过权限」会让浏览器不再被要求批准任何东西**——而那正是这个桥接存在的意义所在。它们之所以提供，是因为两个产品都提供；面板会对它们做标记和告警。改动从下一轮开始生效，因为那是两个产品读取这项设置的时刻。

## 模型、推理强度与配额


两个产品都能枚举自己的模型，也都接受按轮指定模型，所以选择器提供的恰好就是该会话所属产品报告的内容——这里不存在一份会过期的模型名单。推理强度嵌在模型之下，因为两个产品都是这样划定它的作用域的：一个模型接受的档位不等于另一个模型的档位，而一个不接受任何档位的模型就什么都不显示。

`产品默认`是一个真实的选项，不是占位。保持它被选中，就沿用你在 CLI 里自己配好的东西——如果你已经在那边设过模型，这才是对的答案。改动从下一轮开始生效，理由和权限模式一样。

推理强度是滑块而不是一排按钮，因为这些档位是「想得更久」这一条有序的轴，不是五个互不相干的选择。它是原生 range 输入，所以键盘和读屏软件不需要重新实现就能工作，而且它播报的是档位名而不是索引。面板没有对应词汇的档位——Codex 有一个 Claude SDK 没有的 `ultra`——按产品自己的拼法原样显示。

| 产品 | 模型来自 | 通过什么生效 |
| --- | --- | --- |
| Claude Code | 活跃 SDK query 上的 `supportedModels()` | `Options.model` 与 `Options.effort` |
| Codex | App Server 的 `model/list` | `turn/start` 上的 `model` 与 `effort` |

和命令一样，Claude Code 只能在某一轮进行中被问到，所以列表要等面板里任何地方发出过第一条消息之后才出现；在此之前控件会直说，而不是看起来像一个没有模型的产品。Codex 任何时候都能回答。

**只有产品主动给出配额时才显示配额。** Claude Code 对订阅账号以流事件的形式发出它；Codex 有对应的调用，但没有 ChatGPT 登录就拒绝。产品什么都没说的账号就什么都不显示，因为一个 0 或者一个横线会被读成一个数值。当上报了多个额度时显示最紧的那个——那才是会拦住你的那个——其余的在提示浮层里。

## 命令、技能与 MCP


在输入框里打 `/`，会列出该会话所属产品报告自己能做的事，随打字过滤，可用方向键导航。选中一条只会写入产品自己的调用文本，别的什么都不做——桥接从不代替产品执行命令，所以 `/compact` 在这里的含义和在终端里一样，而一个产品改了命令名，这边也不需要改动。

语法是产品的，不是桥接的：

| 产品 | 通过什么报告 | 如何调用 |
| --- | --- | --- |
| Claude Code | 活跃 SDK query 上的 `supportedCommands()` | `/name` |
| Codex | 针对会话工作目录的 `skills/list` | `namespace:skill` |

Claude Code 只能在某一轮进行中被问到，所以它的列表在会话第一条消息之后出现，并在后续每一轮刷新；在此之前面板会说它还没有报告，这和「报告说没有」不是一回事。Codex 任何时候都能回答。

两个产品的 MCP 服务器都按各自报告的状态列出，作为清单——它们不能从输入框调用。

### 为什么没有 `/resume`、`/model` 和 `/clear`

因为它们不是命令。`/resume`、`/model`、`/help`、`/clear` 等等属于 Claude Code 的终端界面，那一层自己画屏幕、自己读按键；而这个桥接驱动的 Agent SDK 没有那一层，所以这些命令在它里面并不存在。`supportedCommands()` 返回的是技能——它自己的文档就是这么写的——这也是为什么你打 `/resume` 得到的是产品自己诚实的 `/resume isn't available in this environment`，而不是桥接编出来的错误。

这些能力本身全都在这里，只是以控件而非打字命令的形式，因为这是 SDK 暴露它们的形状：

| 在终端里 | 在这个面板里 |
| --- | --- |
| `/resume` | `浏览已有会话…` |
| `/model` | 输入框右下角的模型选择器 |
| `/status` | 框上方的上下文用量、框下方的配额 |
| `/permissions` | 权限模式选择器 |

任何被产品真正报告为命令或技能的东西，都会出现在 `/` 列表里，并以产品自己的语法调用。

## 继续一个已有会话


`浏览已有会话…` 列出所选目录下已经存在的原生会话，包括你在终端里开的那些，并把你选中的那个交给产品自己的恢复路径。

**此前的对话会被加载进时间线。** 恢复给回的是**产品**的上下文——这就是恢复的含义——但面板只记录过它自己那些轮次，所以继续一个在终端里开的会话，过去看到的是一个正在干活的 Agent 上面一片空白。现在转录通过各产品自己的 API 读回来，并作为普通事件写下，所以它会持久化、刷新后能重放，也和别的东西一样能撑过主机重启。转录里有一道分隔线标出既有对话到哪里结束。

| 产品 | 转录来自 | 内容是什么 |
| --- | --- | --- |
| Claude Code | `getSessionMessages()` | 消息、思考，以及工具调用及其结果 |
| Codex | 带 turns 的 `thread/read` | 只有消息——rollout 历史里不含工具调用 |

这个差异是产品的、不是桥接的：Codex 存的历史就是不带工具调用，而凭空造出来会比缺着更糟。`thread/items/list` 本该是分页的等价接口，但这个版本的 Codex 对它的回答是「暂不支持」。

保留的是最新的部分，不是最旧的。一个长会话的开头，很少是你为了继续它而需要的东西——在一个真实案例里，那是一条消息后面跟着上百个工具调用——所以留下来的是尾部，而面板会说明更早的条目何时被丢掉了。

枚举走各产品自己的 API——Agent SDK 的 `listSessions`、Codex 的 `thread/list`——绝不通过读 `~/.claude` 或 `~/.codex`。对 Claude Code，这份列表排除了程序化入口，这既是 SDK 为会话选择器所写的做法，也顺带避免了桥接把自己创建的会话再推荐回来。

会话转录路径留在主机上。未知或已过期的定位符会让会话变成 `orphaned`，和主机重启后不再能解析的那种情况一样。

## 侧边栏面板


标题栏右侧的按钮打开第三列，展示 Agent 正在工作的这个项目：上面是查看器，下面是工作目录的目录树。读一个 Agent 刚改过的文件，不必离开对话。

这里的一切都是工作区相对的。目录树和查看器都在会话工作目录之下的路径上工作，所以这个面板持有或发送的任何东西都不是主机的绝对路径——这一点和输入框的主机浏览相反，后者存在的意义恰恰就是那个，并且它明说了。包含关系在符号链接解析之后检查：一个被提交进仓库的链接，不能成为读取它所指向的任何东西的通道。

目录在被打开时才读，不预先读，所以不会为了一棵没人要看的树去遍历一个 monorepo。`.git` 和 `node_modules` 被跳过。点文件会列出，但在你要求之前隐藏。超过 512 KB 的文件被截断并说明这一点，二进制文件会说自己是二进制，而不是渲染出满屏的替换字符。

打开写入之后，这个面板就是一个轻量文件管理器：创建文件或目录、重命名、删除、就地编辑内容。一切都限定在工作目录内，其中三种拒绝是刻意的：

- **创建从不覆盖。** 「新建文件」和「抹掉那个文件」是两种意图，而只有一种被表达了。父目录必须已经存在，这样一次手误就不可能造出一棵没人要的树。
- **删除不递归。** 有内容的目录会被拒绝，并说明原因。一个从浏览器就能触达的递归删除，等于让一次误点就能丢掉一个仓库。
- **文件被动过就拒绝保存。** 读文件时会带一个修订号，写回时把它带上。Agent 就在同一棵树上干活，而一个「缓冲区里是什么就写什么」的面板会悄悄抹掉 Agent 刚做完的事情。不一致时你的文本留在编辑器里，查看器显示较新的那个文件，这样你能在决定之前同时看到两者。

被截断的文件根本不能编辑——保存会把显示出来的那一部分覆盖到整个文件上。

编辑用的是朴素的 textarea，而不是把高亮视图改成可编辑。在彩色 span 上叠一个光标等于重写一遍文本编辑，而做得似是而非，比老老实实用等宽字体编辑一分钟更糟。

在 Profile 配置里设 `allowWorkspaceWrites: false` 可以把这些全部关掉；此时那些控件不出现，而不是出现了然后失败。

语法着色来自 lowlight——把 highlight.js 的分析结果当作树而不是一串 HTML 拿过来，这也是为什么这里渲染的是 React 元素、而面板里根本不存在 `dangerouslySetInnerHTML`。37 种语言，按扩展名挑选并对照已注册的语言核对：未知扩展名显示为纯文本，而不是去猜——因为颜色是在断言一种结构，而断言错了比不断言更糟。

它在客户端产物里占 314 KB 未压缩、上线约 80 KB。如果这比覆盖面更重要，`src/client/code.tsx` 里的 `createLowlight(common)` 可以改成手挑的子集。

语法调色板是样式表里唯一带字面颜色的地方。Harness 暴露了标签、状态和按钮的别名，但没有语法色阶，而从四种语义色里推不出八种可区分的代码色调——所以它带了两套完整的，每个主题一套，而不是让其中一套是另一套的反色。

### 差异页签

当工作目录是一个 git 仓库时，面板的第二个页签显示未提交的内容——对比 HEAD，所以已暂存和未暂存的改动是同一个视图，而这正是一个人说「我改了什么」时的意思。

两种布局。**统一视图**是 git 自己的行序，也是默认，因为面板窄，一列长行比两列折行更好读。**并排视图**把每一处删除和替换它的那处新增配成一对，这样一行被编辑读起来是一处改动，而不是一次删除后面跟着一次无关的插入；某一侧用完时，另一侧留空格——三行被替换成一行不是三处编辑。

差异本身来自 git 的统一输出，而不是在插件里比较文件。git 懂重命名检测、空白选项、文本转换过滤器和二进制文件，而重新实现一遍会在这四件事上全错。

未跟踪的文件会列出，但不带差异块：它们没有更旧的版本可比，而把一整个新文件渲染成一大坨新增，只会把它旁边真正的改动埋掉。面板会说明这一点，并指向文件页签。

## 一轮对话怎么读


一轮是三层：问题、工作、回答。

工作——工具调用、思考，以及 Agent 开场那句「我先看看情况」——折成一行：`2m19s 内处理完 · 4 步`。它在这一轮进行中是展开的，因为那时候看着它才是重点；这一轮结束后就折起来，因为那时候重点是回答。你自己设定的折叠状态优先于两者：既然你打开工作是为了读它，就不该在这一轮完成时被它自己关掉。

回答是这一轮**最后**那条助手消息。它之前的一切都是工作，这也是为什么开场发言会和它引出的那些工具调用一起折走。

有四样东西留在折叠之外，因为它们都不是「通向回答的工作」：你自己的消息、标记恢复转录的那道分隔线、需要你处置的状态，以及错误。失败是一种结果，把它折走就是藏起最值得看的那一行。

例行的状态行——每一轮前后的 `running` 和 `idle`——根本不显示。工具栏实时报告这个，而每个问题和它的回答之间夹两行，正是这套分组要消除的噪音。

## 图片


把截图粘进输入框，Agent 就能看到它。两个产品都原生接受图片——Codex 作为 `image` 输入项，Claude Code 作为 base64 图像块——所以这是图片到达了模型，而不是一个还得告诉它去读的文件。单独一张图片就是一条有效的消息：当图片本身就是问题时，「这是什么」是一个完全合格的提示词。

每张图片同时保存进 `.dsh-bridge-uploads/` 并在消息文本里被引用，所以刷新之后对话仍然读得通。转录里存的是路径而不是字节：一张截图是几百 KB，而事件日志保留两千条，把图片存在那里等于用整份转录换几张图。

类型走白名单：PNG、JPEG、GIF 和 WebP——也就是产品接受的那些。SVG 被刻意排除：它对浏览器是图片，对别的一切都是脚本宿主。每条消息八张图，每张 5 MB。

只有存在图片时才走 Claude Code 的流式输入模式，因为那是承载图像块的方式。每一轮纯文本对话走的路径和从前完全一样。

## Markdown


两个产品都用 markdown 回答，而面板会渲染它：标题、表格、列表、围栏代码、粗体、行内代码。只渲染 Agent 写的——操作者自己的消息保持他打出来的原样，工具的输出留在它的代码块里，因为 markdown 会把它弄坏。

渲染器是写进插件里的，不是引进来的，理由有两条。

**它注入不了。** 它产出的每个节点都是 React 元素，而 React 会转义文本子节点；这里没有 `dangerouslySetInnerHTML`，也没有一个「markdown 转 HTML」的步骤需要某个净化器去追着堵。这一点在这里格外要紧：Agent 的输出不是可信输入——它可以被 Agent 刚读到的任何东西塑造——而这个面板是在一个持有操作者会话的 Harness 里渲染它。

**它是降级而不是失败。** 流式显示会把文本在 token 中间就交给它，所以一个段落经常是一个没闭合的粗体，或者半张表格。任何未终止或不认识的东西，都按打出来的字符原样渲染，也就是 markdown 存在之前面板的行为——所以最坏情况不比旧行为更差。

原始 HTML、图片、引用块、脚注和嵌套列表不支持，按源文本显示。链接会显示它的文字和目标，但不可点击：一个由刚读过不可信文件的模型拼出来的可点击目标，是这个视图不需要的攻击面。

## 轨迹视图


`轨迹`挨着`对话`，回答一个不同的问题：不是说了什么，而是时间花在哪儿、Agent 实际做了什么。一条横跨这一轮时间线的带子——输入、模型、工具——然后每一步一行，带它的参数、结果和耗时，可过滤，下面是合计。

这些全部由面板已经持有的事件推导出来。没有额外的主机调用、没有新的事件类型、也没有额外的留存：每个桥接事件都带时间戳和轮次 ID，这足够算出跨度、顺序和合计。

有两点是刻意的：

**空闲时间被剔除。** 时长算的是这些轮次，不是墙上的钟。一个整夜开着的会话，首尾跨度是若干小时——在一个真实会话上量出来是 `4262m40s`——而其中没有一点是工作。活动的边界取自轮次的开始与完成，而不是事件之间的间隙，因为一个模型思考十秒钟什么都不发，而按间隙判定会把深度思考算成空闲。等待审批仍然计入：那一轮确实还没结束。

**没量到的数值是缺席，不是零。** 没有 token 上报就没有每秒 token 数、也没有缓存命中率。性能视图里的一个 0 会被人当真。

**没有「模型时间 / 工具时间」的拆分，而这是刻意的。** 它看起来能从事件时间戳里推出来，其实不能：那些记录的是产品**选择上报**某件事的时刻，不是它做那件事的时刻。一轮真实的 Codex 对话耗时 2 分 18 秒，却把它所有事件都在最后三秒里交付出来，并且把一条 shell 命令的开始和完成戳成相差 1ms——这个视图的第一版就是从这里算出了「模型 11ms、工具 1ms、7636 tok/s」。所以轨迹现在陈述的是每一步**何时被上报**，而它唯一给出的速率是输出 token 除以整轮时长——后者的分母是桥接自己打的时间戳。

## 锁


设置 → 隐私里为这个面板设置密码。设了就是启用，删了就是停用——密码的存在本身就是开关，所以没有第二个东西需要与它保持同步。

锁定时，面板显示的是密码框**取代**自己，而不是盖在自己上面：主体根本不在 DOM 里。但这只是结果，不是机制。机制在主机侧：桥接的每一个 Remote 方法在没有有效令牌时都拒绝——所以那个输入框并不是拦住人的东西，把它删掉只会让面板不可用，而不会让它敞开。

一次解锁最长 8 小时，闲置 30 分钟失效，两者都由主机计时。设置页里的「立即锁定」会作废**所有地方**的解锁，不只是当前这个浏览器的：从一台你正要离开的机器上锁定，不该留着另一台是开的。主机重启同样会锁上——密码存下来了，解锁没有。

猜密码被两重约束，因为一重不够：校验值是 `scrypt`，每次约 0.15 秒；五次失败后开始锁定，从 30 秒翻倍到 15 分钟上限。锁定期内，连正确的密码也会被拒。

锁屏上写明了它**不**覆盖什么，因为一个人设下密码的那一刻，也正是他形成认知的那一刻。它覆盖这个面板，不覆盖 Harness 的其余部分；而在明文 HTTP 上密码是明文传输的——理由见[面板自己的锁](security.md#面板自己的锁)，给 Harness 本身加密码见 [`examples/proxy/Caddyfile`](../../examples/proxy/Caddyfile)。

## 动画


几乎全是 CSS——悬停、按下、折叠箭头、浮层的入场、上下文用量条的填充。有两样不是，而它们是同一个问题：一个布局尺寸没有第二个可供过渡的关键帧。

**折叠**没法从 `height: 0` 走到 `height: auto`，因为 `auto` 在被布局之前不是一个长度。**侧边栏面板**没法滑动，因为打开它会给主体加上第三个网格列，而一个轨道列表无法与长度不同的另一个做插值——所以它原本是「砰」地出现，对话则横向一跳给它腾地方。

两者都由 GSAP 补间，在 `src/client/motion.ts` 里，它在运行时测量尺寸并逐帧驱动。面板的宽度是从样式表读出来的、不是在代码里重述一遍，所以在 CSS 里把面板加宽，动画也跟着走。两者都把内容多挂载一会儿，刚好够让人看见它收起来；两者落定时都清掉所有内联样式——一个高度被钉在测量值上的折叠，会把它打开之后才流进来的行截掉。

在一份工作行高达 12800px 的真实转录上量过，补间守住了显示器的帧预算，没有自己造成的丢帧。首次绘制时什么都不动：否则一份刚加载的转录、或者一个刚恢复的会话，会把它包含的每一处折叠都当成有人手动打开过一样播一遍。

在 `prefers-reduced-motion` 下两者都不动——折叠和面板直接出现，也就是这套东西存在之前的行为。

GSAP 不在 OSI 认可的许可证之下，见 [THIRD_PARTY_NOTICES](../../THIRD_PARTY_NOTICES.md)。

## 流式输出


两个产品都逐 token 流式输出，主机每收到一个 delta 就立刻转发。但浏览器是通过长轮询读的，所以它收到的是一次往返期间攒下的全部内容——在一轮真实 Codex 对话上量出来是先 11 个字符，然后一下 346 个。这没错，但它看起来不像流式。

所以「到达」和「显示」是分开的：文本按帧计时器逐步显现，步长随积压增长，于是一大批内容在几帧里追上，而不是整块出现，而显现也永远不会被一轮很快的对话永久甩在后面。已完成的回答，以及从恢复会话里读回的转录，都是完整显示的——给它们做动画，会歪曲它们发生的时间。

时间线的行做了记忆化，这是另一半原因：不做的话，每一个 delta 都会重绘一个恢复会话的好几百行，那会拉长往返时间，让下一批更大。
