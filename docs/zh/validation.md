# 验证

## 自动化命令

在 Windows、macOS 或 Linux 上，从项目根目录执行：

```sh
pnpm run build       # host 与 client 的产物和声明
pnpm run typecheck   # host 与 client 两个工程
pnpm run lint
pnpm test
pnpm pack --dry-run
```

`pnpm run check` 按顺序把这五步都跑一遍。

自动化这一轮覆盖：脱敏、不透明 UUID 的稳定性、版本准入、产品健康状态投影、三个主机平台的启动形态、严格的 Typert schema、Profile 的 browse-picker 组合、三轮流式输出、排队、审批、提问、取消（包括某个产品只报告自己被打断、却不带取消标记的情形）、回放重置、持久化恢复、Codex App Server 的生命周期与登录拒绝、Claude SDK 的 resume/流式/交互/取消、客户端的创建/轮询/响应/重连行为、针对随包字典的双语渲染、产品不可用时的诊断、面板内工作目录的归属及其可选的 Harness 发布、目录能力探测及其两条回退路径、样式表的主题令牌与作用域保证、跨两个产品调用语法的命令面板、恢复一个产品原生会话、输入框的键盘处理（含输入法组词）、各产品的权限模式映射、可展开的工具详情、上下文用量，以及针对真实符号链接的文件搜索限定。

## 真实产品冒烟清单

只在一台已经登录过这些产品的可信主机上跑，并且要用将来启动 DSH 的同一套 shell 环境。用一个不含机密源码的一次性测试工作区。

对每个产品：

1. 从浏览器创建一个桥接会话。
2. 完成三轮只需报告「成功/失败」这种笼统事实的对话。
3. 触发一次安全的工具审批，在可行的地方把允许和拒绝都走一遍。
4. 触发一次用户提问，并从浏览器回答。
5. 取消一轮正在进行的对话。
6. 在活动过程中刷新页面，确认五秒内状态恢复。
7. 中断网络路径，确认自动重连且渲染出的事件没有重复。
8. 归档会话，卸载插件。
9. 确认受管进程树已经消失。

在 macOS 和 Linux 上，受管子进程就是解析出的那个可执行文件本身，所以第 9 步就是检查 DSH 没有活着的子进程：

```sh
pgrep -P "$(pgrep -f 'dsh web' | head -1)"
```

在 Windows 上，子进程是包着垫片的 `cmd.exe`，所以要看整棵树，而不是单个进程名。

不要记录真实账号身份、令牌、私有源码、完整提示词、含私密数据的命令行，或含公司信息的模型输出。

## 浏览器零登录证据

对完整的 fake-provider 流程抓一份浏览器 trace，并断言：

- 没有任何请求的主机名命中 Anthropic、Claude、OpenAI、ChatGPT 或产品 API 域名。
- local storage、session storage、IndexedDB、cookie、下载、DOM 文本和 Remote 帧里都不含凭据「探雷」值。
- 不存在任何登录按钮、令牌输入框、OAuth URL 或设备码。
- 只经过批准的、带认证的访问路径才能到达 DSH。

## Codex 0.153.4 与 Claude Code 2.1.266

主机升级到 Codex `0.153.4`、Claude Code `2.1.266`，Codex 的 schema 锁定也随之移到
`0.153.4`。在这两个版本上、通过真实启动的 Web Profile 对真实产品验证过的：

- Codex：建会话、流式回复、一次 `shell` 工具调用（参数详情正常渲染），以及图片输入
  —— 一张纯红栅格图粘进输入框后被正确命名，说明模型读到了那个 data URL，而不只是
  容忍这个字段。
- Claude Code：建会话与一次 `Bash` 工具调用，配的是锁定的 Agent SDK `0.3.220`。
  当时 SDK 自己的最新版是 `0.3.266`，未采用。
- schema 是逐个比对而非假设：没有消息被删除、没有联合分支被丢弃，并且——按判别式而
  非位置来匹配联合——本桥读取的任何地方都没有新增必填字段。`Thread.projectId` 确实
  变成了必填，但它落在本桥从不校验的那些响应上。

这两个版本上**未**重跑的：Codex 侧的审批与提问弹窗、steer、interrupt、MCP、连接丢失、
登录拒绝。`0.147.0` 与 `0.153.4` 之间的 minor 完全没跑，仅凭 schema 对比准入。

## 真实浏览器验证记录

- 官方 DSH Loader 最初暴露了三个自动化组件测试没抓到的集成缺陷：产物里残留的原始 Host 装饰器、客户端 Remote 注入的生命周期循环，以及因为脱敏了布尔字段 `secret` 而导致的 question schema 失败。三者都已修复，并由构建或单元测试覆盖。
- 最后一次反复出现的回归暴露了第四个边界缺陷：设备码的匹配模式会把纯数字的 UUID 段也脱敏掉，从而改写交互 ID 或原生定位符。现在文本脱敏过程中 UUID 受保护，而独立出现的设备码仍然被脱敏；聚焦的核心测试集在最终全量运行之前连过五轮。
- 390 × 844 的移动端布局最初溢出到 612 CSS 像素，主面板只剩 54 像素宽。响应式布局现在稳定在 374 CSS 像素之内，会话栏和主栏都能拿到全部可用宽度。
- 真实的 Codex 与 Claude 会话复用了主机既有的登录状态。没有在浏览器里做过任何登录，也没有读取任何凭据文件、令牌、cookie、账号身份或操作系统凭据库。
- 远程 Web Profile 的 browse 选择器从浏览器里走过一遍：在 DSH 的目录对话框里编辑路径选中测试工作区，然后完成登记，全程没有打开主机原生的文件夹选择器。组合出的加载器用的是 `@deepseek-ai/dsh-host-directory-picker-browse` 和 `@deepseek-ai/dsh-client-ui-directory-picker-browse`。
- Fake Provider 的浏览器流程走完了流式输出、审批允许、审批拒绝、回答提问、取消和刷新页面回放。审批拒绝让那个 fixture 轮次以预期的 provider-start-failed 状态结束，并且没有持久化任何放行规则。
- 模型选择针对两个真实产品做了端到端验证。Codex 的选择器从 `model/list` 列出了五个真实模型；选 `GPT-5.6-Sol` 加 effort `high` 之后，产品答出 `gpt-5.6-sol`，上下文窗口从 1.0M 变为 258k。Claude Code 的选择器在会话第一轮之前正确地处于不可用状态——一个支持选择但此刻还问不到的产品——之后列出 Default/Opus/Fable/Sonnet/Haiku；选 Haiku 后产品报告 `claude-haiku-4-5-20251001`，窗口 200k。该选择在主机重启后仍然有效。推理强度档位随各产品而定：`GPT-5.6-Sol` 提供六档，含 Codex 自己的 `ultra`，面板原样显示它，因为我们没有对应的词；而 Haiku 4.5 一档也不提供，面板就什么也不显示。
- 配额在这台主机上什么都不显示，而这正是正确的渲染：该账号基于 API key，所以 Claude Code 不发 `rate_limit_event`，而 Codex 的 `account/rateLimits/read` 回的是 `chatgpt authentication required to read rate limits`。两条路径都有带上报数值的单元测试覆盖。
- 输入框的文件按钮列出了工作目录里的文件和文件夹，对目录插入带尾斜杠的 `@notes/`、对文件插入 `@README.md`，并且能在同一份草稿里累积两者。
- 语音输入在 Chrome 里出现，悬停时带音频上传的告知，而在 jsdom 下不出现——这个特性检测是一道真的门，不是占位。
- 有一个真实缺陷只在浏览器里量出来：上下文用量条的填充是一个非 flex 父元素里的 `<span>`，所以它是行内盒，而行内盒会忽略以百分比传进来的行内宽度。这根条从写出来那天起，在每个主题、每个会话里都恒定为空；只看文本的验证漏掉了它，而 jsdom 不做布局计算。已修复，并由一条样式表守卫钉住：任何以行内方式设定尺寸的类都必须声明 display。
- 从浏览器上传在 Chrome 里针对真实 Codex 做了端到端验证。发了两个文件，其中一个故意命名为 `../../../../escaped.txt`；两者都落进了 `.dsh-bridge-uploads/`，穿越部分被重建掉了，并确认上层目录都是空的。之后 Agent 自己主动跑了 `cat .dsh-bridge-uploads/from-browser.txt`，把内容一字不差地引了回来。
- 一次浏览器检查抓到了单元测试绕过去的一个缺陷：`webkitdirectory` 是在挂载时的 effect 里设置的，但那个 input 只在上传页签打开时才存在，于是文件夹按钮打开的是普通文件选择器。而测试用 `:not([webkitdirectory])` 选中了那个普通 input，两种情况下都能过。两者都已修复——属性改为跟着可见页签走，测试现在断言两个 input 中恰好有一个带这个属性。
- 面板的浮层点击空白处关不掉，而权限模式菜单从写出来就一直有这个问题。现在三者都用 Harness 自己的 `useDismissOnOutsidePointer`，并且都能用 Escape 关闭，逐一断言。
- 输入框的状态行拿它正在读的那个仓库对过账。面板显示 `master +473 −14 no upstream`；`git diff --numstat HEAD` 加起来正好是 `+473 −14`，而这个仓库确实没有远端，所以 git 是不输出 `branch.upstream` 这个头，而不是给一个空的。一轮真实 Claude 对话之后的 token 消耗读作 `24k total`，悬停显示 `10 input / 29 output / 24k cache read / 415 cache write`——和一次针对热缓存的短交流相符。
- 加载已恢复会话的转录在 Chrome 里针对两个产品都验证过。Codex 为一个验证线程返回 7 条——3 条用户消息、4 条 Agent 消息，正是 `thread/read` 报告的内容，因为它的 rollout 历史里不带工具调用。Claude Code 返回 240 条，其中 154 条是可展开的工具行，分隔线上写着「更早的条目未加载」。有三个缺陷只在这里、只针对真实的长转录才暴露：第一版是从**前面**截断的，于是一个 977 条消息的会话显示的是它的开头——一条用户消息后面跟着上百个工具调用——而不是最近的对话；适配器自己的裁剪对引擎不可见，于是面板说的是「240 条」而不是「更早的未加载」；还有，带图片发出的用户消息到达时是内容块而不是字符串，于是每条配图的消息都被静默丢掉了。三者都已修复，且各有一个测试钉住。
- 一条值得记下的方法论：有两轮验证读的是**此前**的桥接会话，其历史早已由旧代码写好，于是看起来像是修复没生效。历史事件和别的事件一样是持久化的，所以要测试投影的改动，必须新建一个会话来恢复。第三轮先把所有会话都归档了。
- 推理强度滑块针对一个有六档的模型检查过：`min=0 max=5 step=1`、`aria-valuetext` 读出档位名而不是索引、画出六个刻度、最右端选中 Codex 自己的 `ultra`。它的刻度起初是看不见的——叠加混合在这个主题接近纯黑的强调色上会消失——现在改用差值混合，在轨道的两半上都能看清。
- 侧栏折叠按钮移到了标题栏左侧，也就是它作用的那一侧。折叠状态下，那条窄栏用来切换会话，而不是摆一个「把自己所在的面板重新打开」的第二个按钮：52px 侧栏、1108px 主区，切换会话不需要展开。
- 浏览主机文件系统针对真实 Codex 做了端到端验证。输入框的第三条路径列出了 `/Users/mac`（13 个目录），然后是 `dsh-bridge-validation`，在那里显示出了三个**文件**——而 Harness 自己的选择器对这个目录报的是「没有子目录」——这正是本功能自己实现、而不是委托给 `workspaces.listDirectory` 的原因。选中一个之后插入了 `@/Users/mac/dsh-bridge-validation/bridge-check.txt`，Agent 自己主动跑了 `cat -- /Users/mac/dsh-bridge-validation/bridge-check.txt` 并引回了内容。
- 消息对比度：操作者的消息原本是白卡片上 5% 的色调、92% 宽度，这种差别得刻意去找才看得出。现在是 10%、78% 宽，标签用更重的墨色，Agent 的卡片带一道可见的边——三个信号，因为一个不够。
- 字体栈为 Windows 读者做了修正，而这个修正是推理出来的、不是验证出来的：这一轮只在 macOS 上跑，没有观察过 Windows 的渲染。修掉了两个客观错误。`Helvetica Neue` 排在 `Segoe UI` 前面，而它在很多 Windows 机器上确实存在，因为 Adobe 的安装程序会装进去——结果同一句话里的拉丁字母用印刷体在 ClearType 下渲染，而中文落到了雅黑。另外新字体一个都没写：Windows 11 自带 `Segoe UI Variable`，`Microsoft YaHei UI` 才是界面版本，而等宽栈里既没有 `Cascadia Mono` 也没有 `Consolas`，最后落到了 Courier New。在 macOS 上确认了这个栈仍然首选 `-apple-system`，并且 `Helvetica Neue` 已经不在了。
- 流式输出是量出来的，不是假设的。在一轮真实 Codex 对话中每 80ms 采一次 DOM，只看到四次更新，其中一次一下来了 346 个字符：主机确实每收到一个 delta 就立刻转发，但长轮询交付的是一次往返期间攒下的全部内容，而且每个 delta 都在重绘整条时间线。把「到达」和「显示」分开、并对行做记忆化之后，同一个提示词产出了十次更新，每次 20–100 个字符，批量到达时能看到明显的追赶。
- 轨迹视图针对一轮真实 Codex 对话检查过，而它的第一版错在只有真实数据才能显出来的地方。它对一轮耗时 2 分 18 秒、产出 84 个输出 token 的对话，报的是「model 11ms · tools 1ms · 7636 tok/s」。那些事件全部到达于该轮最后三秒内，而 shell 命令的开始和完成时间戳相差 1ms——所以时间戳记录的是产品**选择上报**的时刻，不是它干活的时刻。于是模型/工具的拆分和每步耗时被直接删掉，而不是加个注解留着；视图现在陈述每一步是何时被上报的，并按输出 token 除以整轮时长给出速率——整轮时长是桥接自己打的时间戳。时长也排除了空闲时间，其边界取自轮次的开始与完成，而不是事件之间的间隙：按间隙判定会把模型静默思考算成空闲，而对一个整夜开着的会话做首尾相减读出了 `4262m40s`。
- Markdown 渲染针对一个真实 Codex 回答验证过：一个二级标题、一个单元格里带行内代码的两列表格，以及一个含粗体的项目符号列表，全都变成了真实元素，卡片里没有残留字面的星号或竖线。渲染器只产出 React 元素，测试通过喂给它 `<img onerror>`、`<script>` 和 `<b>` 并确认没有一个变成元素来断言这一点。
- 一个布局缺陷是量出来的、不是看出来的：视图页签盖住了转录内容，因为 `.lab-main` 是三行网格——工具栏、主体、输入框——而页签加上第二个视图是作为额外的网格子元素加进去的，于是有两个落进了同一行。现在它们嵌进了一个 flex 列子元素里，并确认页签自己的中心点命中的是页签本身，而不是画在它上面的东西。
- 轮次分组针对一轮真实 Codex 对话的整个生命周期验证过。运行中摘要读作 `已处理 31s · 1 步`、展开状态、并一直数到 `1m52s`；完成后变成 `2m19s 内处理完 · 4 步`、折叠状态，转录里正好剩三样东西——问题、摘要条、回答。展开后恢复出开场发言和三次 shell 调用，顺序与实际发生一致，再折叠又收了回去。过程中暴露一个缺陷：还没有回答的轮次，其 `foldable` 是以「回答存在」为条件的，于是它的工作既是折叠的又展不开——表现为工具行消失了而且没法找回来。
- 粘贴图片针对真实 Codex 做了端到端验证，而证据是那张图本身、不是管道：一张画着 `BRIDGE-IMG-7431` 的 canvas PNG 被粘进输入框，Agent 答出了 `BRIDGE-IMG-7431`。它是作为图像输入到达模型的，不是作为文件引用。待发时缩略图出现、发送后清空，消息行读作 `已发送 · 1 张图片`，PNG 以真实尺寸落进了 `.dsh-bridge-uploads/`。在依赖它之前，先针对 0.147.0 验证过 Codex 接受 data URL，因为 schema 只把那个字段标成字符串。
- 侧边栏以本仓库作为工作区验证过：主体变成三列（288px / 452px / 420px），目录树把目录排在文件之前并带大小，`src` 只在被打开时才读取，`src/types.ts` 渲染出 824 个行号和七种 token 类别——关键字 #cf222e、注释 #6e7781，确认调色板确实生效而不是落空。限定关系在 `tests/unit/workspace-files.spec.ts` 里针对真实符号链接断言，包括一个指向工作区之外的，因为这里读取的是文件内容，而主机浏览并不读内容。
- 发现有两条守卫只作用于 `index.tsx` 一个文件，而拆出一个组件就能静默绕过它们：primitives 的 stub 检查放过了 `IconFolderOpen16`，表现为「undefined is not a component」的失败，样式表检查有同样的盲区。现在两者都扫描每一个客户端 JSX 文件。另外，一条没有作用域的 `.hljs-keyword` 规则本会把周围整个 Harness 里所有高亮块重新上色——选择器守卫抓住了它，现在这些规则都限定在查看器之下。
- 文件写入在一次性工作区里做了端到端验证，包括最要紧的那种情形。创建一个文件、打开、编辑、保存——落盘的字节是对的——然后在编辑器仍持有它时从外部修改它。保存被拒绝，操作者的文本留在编辑器里，查看器切到较新的文件，而**外部的改动完好无损**。创建、重命名、删除各自从目录树上走通，没有留下残留。过程中暴露一个缺陷：`rm` 不带 `recursive: true` 会拒绝目录，而加上那个参数恰恰就是我们要避免的递归删除——`rmdir` 才是对的，它自己就会在非空目录上失败。
- 过期写入的检测在验证过程中重写了。它原本匹配失败的 error code，而那是**传输层**的码、不是主机的 `BridgeError` 码，于是那条解释从来没出现过。现在它重新读一遍文件并比较修订号，这回答的是真正的问题——它在我们脚下动过没有——而不依赖载体如何给自己的错误命名。
- 差异页签针对一个专为此建的真实 git 仓库验证过。`sample.js +2 −1` 和一个未跟踪文件是从 git 自己的 numstat 与 status 列出来的。统一视图把删除显示在旧文件第 3 行、两处新增显示在新文件第 3、4 行，上下文两侧的行号都对。并排视图把那处删除和替换它的那处新增配在同一行上，并为多出来的那处新增留了恰好一个空格——这种渲染说的是「一行改了、一行加了」，而不是「两处无关的编辑」。
- 面板的锁是直接对着 `/api` 验证的，因为只有这个证明算数：一道传输层不强制的密码屏，离「什么都没有」只差一条 `curl`。设了密码之后，`catalog`、`sessionsList` 和 `hostList` 在空令牌和伪造令牌两种情况下都被拒——拿不到产品列表、会话列表、主机目录。限速用同样方式量了：五次错误各花约 0.15 秒的 scrypt，第六次在 0.06 秒内就被拒（哈希都没跑），`lockedOutUntil` 指向 30 秒后；锁定期内连正确密码也被拒。随后重启主机，显出设计中的那道分界——`configured: true`、`unlocked: false`、锁定计数已清——再用正确密码拿到一个 43 字符的令牌，带着它 `catalog`（2 个产品）、`sessionsList`（6 个会话）、`hostList`（65 个条目）全部通过。
- 有三个缺陷只在真实浏览器里才暴露，其中一个是 fail-open。锁的第一次状态读取发生在插件 boot 期间、Remote face 挂载之前，于是抛异常；未被捕获的 rejection 逸入 boot 链，导致挂载没能完成，后续每次调用都报「no longer mounted」。更糟的是，`locked` 把「状态未知」当成了「未锁定」，于是面板照样把自己渲染出来，而主机那边什么都在拒——这种保护在操作者看来像不存在，对任何人都不成立。现在那次读取不会抛，「未知」是一个独立状态、既不渲染面板也不渲染密码框，并且有重试来覆盖 boot 竞态。第二个：注入令牌的代理把 `receiver` 传给了 `Reflect.get`，而它包裹的 face 本身也是个 Proxy、要按自己的挂载表解析方法——于是所有经代理的调用都在错误的对象上查方法，而原始 face 一切正常。第三个：面板的 catalog 加载和长轮询在锁着的时候就跑，失败后错误粘住且无人重试；现在两者都以令牌为依赖，于是「解锁」这个动作本身就是重试。
- 「给整个 Harness 加密码」这一半，是通过读 `dsh-host-webserver` 确认为**插件做不到**（而不只是难做）：它只提供 `register`（重复路径抛错，且「注册顺序不影响请求」）、`registerUpgrade`（重复抛错）、`registerFallback`（独占，已被 SPA 占用，第二次注册抛错）和 `tapIndex`。没有中间件座位，而浏览器传输是 `dsh-client-connection` 注册在 `/api` 的前缀路由加两个 WebSocket 升级。用更长的前缀去影子覆盖它在机制上可行，但被否决了：拿不到原 handler 的引用可以转发，而且 DSH 一升级就会崩。改为提供一份反向代理配方。
- 安全的只读工具，可能因为产品自身在主机上既有的权限策略而被放行、根本不产生提示。桥接从不自己合成审批；只有原生产品请求时它才显示一个决定。
- 那两个不是 CSS 的动画是量出来的，不是眼估的。在一份工作行高达 12800px 的真实 Claude 转录上切换折叠，120Hz 屏幕上帧间隔中位数 8.4ms，对照空闲基线 8.3ms，只有两帧超过 24ms——都在开头，而且都是 React 挂载这些行的成本、不是补间，所以不需要为高度设上限。侧边栏展开时把 `--lab-side-width` 从 0 走到 419px 再清掉；而它的收起是直接跳到 0 的。那是个有真实成因的真实缺陷：一个只以内联形式设置过的自定义属性，在展开动画结束清掉它之后就没有计算值可供**起始**，于是 GSAP 找不到能解析的东西。现在收起会自己声明起始值，除非它正在打断一个展开中的补间。折叠和侧栏最后都落在样式表描述的状态上，所有内联样式都被清干净。
- 滚动锚定检查过，并且刻意没有改。展开一个 12800px 的折叠会把触发按钮下面的一切都推走，这是对的：你点不到看不见的按钮，所以视口上方永远不会有东西移动。
